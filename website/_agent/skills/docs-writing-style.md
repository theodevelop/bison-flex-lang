# Docs Writing Style

- Write for developers who are editing parser and scanner files in VS Code.
- Start pages with a short practical summary.
- Explain concepts progressively: what it is, why it matters, how to use it, and where it can surprise you.
- Use compact examples that fit on one screen.
- Avoid marketing exaggeration. The docs should feel calm, precise, and useful.
- Do not copy official manuals. Summarize in original words and link to the official reference.
- When a feature depends on installed tools, settings, generated files, or workspace shape, say so clearly.
- Use stable terminology for released V1 features and preview terminology for V2.
